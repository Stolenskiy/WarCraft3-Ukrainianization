# Як долучитися до wc3-ua-voice

Дякуємо, що заглянули! Проєкту потрібні два типи людей — і одному з них
**взагалі не потрібен код або комп'ютерна магія**: лише гарне вухо та рідна
українська мова.

> **Найпростіший старт — озвучити юніта своїм голосом:** покрокова інструкція в
> [README → «Як долучитися локально»](../README.md#як-долучитися-локально-озвучити-своїм-голосом).

**Загальні правила для всіх:**

- Проєкт фанатський і некомерційний (див. «Етика і ліцензії» в README).
- Голоси реальних акторів не клонуємо для публічного поширення.
- Уся текстова робота фіксується у **voice bible** (`docs/voice-bible/`) —
  це єдине джерело правди про те, як звучить кожен персонаж.
- У текстах — жива українська мова: без суржику, без русизмів («зроблю»,
  а не «сделаю»; «тикання», а не «кликанье»).

## Голоси спільноти (PR зі своїм голосом)

Це шлях для тих, хто записує дублі в студії (`make studio`).

1. Затвердіть дублі в студії, потім «Голоси спільноти» → «Опублікувати мій голос» (або `make publish-voice AUTHOR=<нік> CONSENT=1`).
2. Виконайте підказані команди: `git switch -c voices/<нік>`, `git add voices/<нік>`, `git commit`, `git push -u origin voices/<нік>`, `gh pr create`.
   Змінюйте лише `voices/<ваш нік>/` — PR, що чіпає чужі пакети або інші файли, не прийматиметься.
3. `make check` (включно з `check-voices`) має бути зеленим: FLAC 22050 Hz mono 16 біт, ≤ 1 МБ, 0.2–30 с, кожен файл у `manifest.json`
   зі збіжним sha256, репліка є в `data/inventory-units.csv`, без сторонніх файлів.
4. Повторна публікація синхронізує пакет: оновлені файли замінюються, зняті з вибору — видаляються.

**Ліцензія й згода.** Живі записи пакета — **CC BY 4.0** (з вказанням автора — вашого нікнейму), а **ШІ-репліки (`"ai": true`) — CC BY-NC 4.0**, лише некомерційно (ADR 0007: ваги Fish — Fish Audio Research License); `publish` ставить це сам. Публікуючи, ви підтверджуєте, що
це **ваш власний голос** (`consent: true` у `voice.json`) і що не публікуєте чужі записи. Не клонуйте чужі голоси, не додавайте
оригінальне аудіо гри чи `reference*/` — публікатор експортує лише ваші затверджені дублі. **Приватність:** нікнейм — не справжнє
ім'я; пошта й контакти заборонені (`@` у `voice.json`/`manifest.json` валить перевірку); FLAC без метаданих.

**Розмір.** ≈ 40 КБ на репліку в FLAC (≈ вдвічі менше за wav); увесь склад одного автора ≈ 60 МБ. Поки що звичайний git —
достатньо; коли пакетів побільшає, розглянемо Git LFS або GitHub Releases.

## a) Редактор тексту (без коду)

Це найпотрібніша роль. Ваш результат — українські фрази та опис характеру,
які потім синтезує TTS. Комп'ютерний досвід не потрібен.

### Крок 1. Виберіть юніта з backlog

Відкрийте [`data/inventory-units.csv`](../data/inventory-units.csv) — це
інвентар усіх 2401 голосових файлів (155 типів юнітів). Колонки, які вам
треба знати:

- `race` — раса (human, orc, undead, nightelf, creeps…);
- `unit_folder` — ім'я юніта (наприклад `Peon`);
- `phrase_type` — тип репліки: confirm (підтвердження), question (питання),
  annoyed (дражнилки), confirm_attack (йду в бій), death (смерть),
  warcry (клич), ready (готовність);
- `duration_sec` — тривалість оригінальної фрази **у секундах**.

Перевірте статус раси в `docs/voice-bible/README.md` (розділ «Статус»):
люди готові, нічні ельфи в роботі, **орки та нежить повністю відкриті**.
Домовтеся про юніта в issue, щоб двоє не робили одного.

### Крок 2. Послухайте російського еталона

Російська озвучка лежить у `reference/units/<раса>/<юніт>/`. На macOS:

```bash
afplay reference/units/orc/Peon/peonyes1.wav
```

Слухайте не переклад, а **характер**: темп, настрій, куди він «тікає» голосом.
Тексти оригіналів (російські розшифровки) у git не зберігаються (ADR 0005): один раз виконайте `make transcripts-local`
(потрібні референси з RU-мовного пакета: `make refs`), або `make transcribe` (Whisper, `reference/units/`) —
вони з'являться в `data/local/transcripts-<раса>-<юніт>.json`. У git лишаються лише тривалості.

### Крок 3. Опишіть персонажа і напишіть фрази

Додайте/розширте аркуш юніта в `docs/voice-bible/<раса>.md` за шаблоном
з `docs/voice-bible/README.md` (готові приклади — `human.md`, `nightelf.md`):

```markdown
### Peon — Піон
**Роль/архетип:** ...
**Характер:** 2–3 риси, які чути в голосі.
**Тембр:** вік, стаття, забарвлення, опора, швидкість мовлення.
**Обробка (race chain + індивідуальні відхилення):** ...
**Мовна манера:** звертання, лексика, типові конструкції.

| Фраза | Український текст | Як озвучувати (емоція, темп, прийом) |
|---|---|---|
| yes1–4 | «...» | ... |
```

Колонка «Як озвучувати» — не прикраса: саме нею керується генерація й
відбір варіантів. Пишіть там емоцію, темп і прийоми («з видихом-зітханням»,
«кричить, але не верещить»).

**Правила тексту:**

1. **Значення = оригінал.** Підтвердження лишається підтвердженням,
   дражнилка — дражнилкою. Не вигадуємо нових реплік.
2. **Хронометраж.** Українська фраза має вписуватись у тривалість оригіналу
   (`duration_sec` в інвентарі). Не влазить — скорочуйте текст, а не «нехай
   трохи затягне».
3. **Жива мова.** Без суржику й русизмів; розмовна, не канцелярська.
4. **Харизма.** Дражнилки (pissed) — душа юніта: саме їх гравці кликають
   по п'ять разів підряд. Тут можна сміятися.

### Крок 4. Комітьте

- Гілка на расу: `git checkout -b voice-bible/orc`.
- **Один коміт = один юніт**:

```bash
git add docs/voice-bible/orc.md
git commit -m "voice-bible(orc): Peon — аркуш персонажа"
```

Pull request у `main` — у описі коротко: який юніт, які фрази послухали,
де сумнівалися (наприклад, «peonwhat4 не влазить у 0.9 с — скоротив»).

## b) Генератор озвучки (з середовищем)

> ⚠ Станом на 2026-11 локальні TTS (Fish, XTTS, Piper) **не пройшли планку якості** — основний
> шлях зараз запис власним голосом (README). Розділ лишається для експериментів і ElevenLabs.

Потрібен Mac з Apple Silicon (усі наші інструменти працюють через MLX/MPS)
і ~15 ГБ вільного місця.

### Крок 1. Середовище

Потрібен [uv](https://docs.astral.sh/uv/). Два ізольовані середовища,
що важкі залежності не сварилися:

```bash
# основне: Whisper + Piper + XTTS
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python mlx-whisper piper-tts coqui-tts

# Fish Speech S2-Pro (окреме, бо тягне torch)
uv venv .venv-fish
uv pip install --python .venv-fish/bin/python -e tools/fish-speech
```

Моделі (лежать у `models/`, у git **не** комітяться):

- `models/piper/uk_UA-ukrainian_tts-medium.onnx` — україномовний Piper;
- `models/fish-s2-pro/` — ваги Fish Speech S2-Pro (з Hugging Face,
  `fishaudio/s2-pro`, codec.pth у тому ж репозиторії);
- XTTS-v2 тягнеться з Hugging Face при першому запуску — скрипт шукає його
  в `~/.cache/huggingface/hub/models--tts-hub--XTTS-v2/` (шлях зашитий
  у `tools/gen_poc.py`).

Еталонна озвучка (`reference/`) і згенеровані wav (`audio/`) теж не в git —
див. `.gitignore`.

### Крок 2. Згенеруйте одну фразу з Fish Speech (3 команди)

Приклад: піон, фраза `peonyes1` («Зроблю.»). Еталон — російський wav,
його український текст — у voice bible.

**1) Підняти TTS-сервер** (один раз на сесію; з кореня репозиторію):

```bash
.venv-fish/bin/python tools/fish-speech/tools/api_server.py \
  --listen 127.0.0.1:8080 \
  --llama-checkpoint-path models/fish-s2-pro \
  --decoder-checkpoint-path models/fish-s2-pro/codec.pth \
  --decoder-config-name modded_dac_vq
```

**2) Синтезувати фразу з клонуванням тембру** (еталон = російський wav,
еталонний текст = російська розшифровка з `data/local/transcripts-orc-peon.json`):

```bash
.venv-fish/bin/python tools/fish-speech/tools/api_client.py \
  -u http://127.0.0.1:8080/v1/tts \
  -t "Зроблю." \
  -ra reference/units/orc/Peon/peonyes1.wav \
  -rt "Делаем." \
  --no-play \
  -o audio/experiments/peon/peonyes1_fish
```

Клієнт збереже `audio/experiments/peon/peonyes1_fish.wav`.

**3) Порівняти варіанти на слух:**

```bash
afplay reference/units/orc/Peon/peonyes1.wav   # оригінал
afplay audio/experiments/peon/peonyes1_fish.wav
afplay audio/experiments/peon/peonyes1_piper.wav
afplay audio/experiments/peon/peonyes1_xtts.wav
```

Кожен варіант — окремий файл `_<система>.wav` у `audio/experiments/<юніт>/`;
угоди про те, який голос переміг, фіксуються в таблиці рішень у voice bible
(див. методологію). XTTS вимагає транслітерації (і→и, ї→йи, є→е, ґ→г) і
мовного тегу `ru` — це вже зроблено в `tools/gen_poc.py`.

### Крок 3. Перевірка в грі

Механізм — loose-файли в корені гри (деталі: `docs/integration.md`):

```bash
cp audio/experiments/peon/peonyes1_fish.wav \
   "/Applications/Warcraft III Classic/Units/Orc/Peon/Peonyes1.wav"
```

- Ім'я та шлях мають **точно** повторювати оригінальні (`Peonyes1.wav`,
  не `peonyes1`).
- `Allow Local Files` має бути ввімкнено (репак робить це сам; перевірити:
  `defaults read "com.blizzard.Warcraft III Public Test" "Allow Local Files"`).
- Запустіть бій, клацніть юніта, послухайте.

### QA-чекліст перед PR

- [ ] Тривалість не довша за оригінал +10% (`afinfo файл.wav` → estimated
      duration, порівняти з `duration_sec` в інвентарі).
- [ ] Нема кліпінгу (не «пересвічений» верх, чисті піки без спотворень).
- [ ] Розбірливо: прогнати через Whisper і звірити розшифровку з текстом
      (ідея для автоматичної перевірки WER — у планах, поки вручну).
- [ ] Послухано на ігровій гучності в грі, не лише в навушниках.
- [ ] Тембр/характер відповідають аркушу в voice bible.
- [ ] Файл покладено в грі й фраза грає замість російської.

**Шаблон опису PR:**

```markdown
Юніт: Peon (orc), фраза: Peonyes1
Текст: «Зроблю.»
Система: Fish Speech S2-Pro, референс peonyes1.wav
Тривалість: оригінал 0.6 с → згенеровано 0.6 с
Перевірено в грі: так, клік по піону, грає українською
Послухати: audio/experiments/peon/peonyes1_fish.wav
```

## c) Озвучення місій (кампанія) — плани

Melee — перша ціль, але кінцева мрія — **кампанійні місії українською**:
RoC і TFT, від «Chapters» до сінематиків. Це великий обсяг, і ми шукаємо
людей, які хочуть підготувати його заздалегідь.

Майбутній робочий процес (зараз **в планах** — жодного з цих кроків ще
немає в репозиторії):

1. **Витягнути діалоги місій** з російської локалізації (id диалогів
   місій відрізняються від юнітових — потрібне окреме дослідження).
2. **Транскрибувати** тим самим Whisper-конвеєром (`tools/transcribe.py`).
3. **Адаптувати текст** з єдиним **глосарієм термінів** (Лордерон,
   Кель'Тас, Плаваючий палац… — щоб Артас у всіх місіях звався однаково;
   глосарій у планах, база — таблиці `warcraft-in-ua`).
4. **Згенерувати по персонажах** — у кампанії героїв небагато, зате кожен
   має сотні реплік: тут voice bible із повним аркушем персонажа окупиться
   найбільше.
5. **Синхронізувати з сінематиками** — відео не переробиш, тому текст
   доведеться підганяти під хронометраж жорсткіше, ніж у melee.

**Що можна робити вже сьогодні:** готувати адаптації текстів місій тим самим
шаблоном voice bible — аркуші персонажів на кшталт «Артас», «Джайна»,
«Тралл» із характером, тембром і манерою мовлення. Позначайте такі аркуші
**«кампанійний обсяг»** (як це зроблено з Капітаном у кінці `human.md`),
щоб їх не плутали з melee-юнітами. Коли дійде до генерації — ці аркуші
стануть фундаментом.

## Для AI-агентів (PR, створені агентом)

Агентський PR — такий самий PR: його читає людина, тож він має бути малим і перевіреним.

1. Почніть з [AGENTS.md](../AGENTS.md) (команди, карта, жорсткі межі), потім `docs/STATUS.md`. Працюйте у власній гілці/worktree.
2. Перед пушем: `make verify` (≤ 20 с); для змін студії — `make check`. `make hooks` вмикає pre-commit (guard + ruff).
3. Заборонено в PR: аудіо й ресурси гри, `reference*/`, `game-files/`, `.env*`; зміни в теці гри; `.claude/settings.json`;
   корпоративна пошта; рядки атрибуції («Co-Authored-By», «Generated with»). `make guard` і CI це ловлять.
4. У PR вкажіть: що змінено, які команди запускали, що перевірено вручну, а що ні. Не змінюйте чужі `voices/<нік>/`.
5. Змінили API/поведінку — оновіть docstring `server.py`, `tools/studio/README.md`, тест і (за потреби) `docs/GLOSSARY.md`;
   тест `tests/test_docs_sync.py` падає при розбіжності. Зміни стану — у `docs/status/<гілка>.md`, не в `STATUS.md`.
6. Повторювані процедури — `docs/runbooks/`. Нетривіальне рішення — ADR у `docs/decisions/` (≤ 25 рядків).
7. Ліцензії: код MIT, живі записи в пакетах CC BY 4.0, ШІ-репліки CC BY-NC 4.0 (`voices/LICENSE.md`, ADR 0007). Клонувати можна лише власний голос; референси — лише власні дублі, ніколи `reference*/`; нові двигуни ШІ — `docs/runbooks/add-ai-engine.md`.
